# Workflow разработки с агентом

Воспроизводимый цикл для этого репозитория. Основан на harness из
`docs/adr/0001-agent-harness.md`.

## Цикл

1. **Проверить точку отката**
   ```bash
   git status
   ```
   Если рабочее дерево грязное и предстоит рискованное изменение — сначала коммит
   или новая ветка.

2. **Сформулировать задачу**
   - Что нужно получить и как поймём, что готово.
   - Что нельзя трогать.
   - Если деталей не хватает — агент обязан задать минимум 3 уточняющих вопроса
     (это enforced хуком `clarify-before-edit.mjs`).

3. **Получить план**
   Для задач больше одной правки — сначала план, потом изменения. Plan mode
   удобен как чекпоинт: до подтверждения файлы не меняются.

4. **Внести изменения**
   Небольшими шагами, по одной причине на шаг. После каждого шага —
   проверки, а не «в конце разберёмся».

5. **Проверки**
   - Автоматически на `Stop`: `lint` + `typecheck`.
   - Вручную перед сдачей:
     ```bash
     npm run lint
     npm run typecheck
     npm run build
     ```
   - Для UI — `ui-verify` (скриншоты и проверка сценария).

6. **Зафиксировать результат**
   ```bash
   git add <файлы>
   git commit -m "<что и зачем>"
   ```
   Коммит — это чекпоинт: к нему можно вернуться, его можно отменить.

## Что где проверяется

| Проверка | Когда | Команда |
|---|---|---|
| Линт | автоматически на `Stop` и вручную | `npm run lint` |
| Типы | автоматически на `Stop` и вручную | `npm run typecheck` |
| Сборка | вручную перед сдачей | `npm run build` |
| Сценарий в браузере | вручную, для UI-изменений | `ui-verify` |

## Если хук заблокировал ход

1. Прочитать причину в сообщении хука: там конкретные ошибки, а не общая оценка.
2. Исправить ошибки и завершить ход снова — хук пропустит, когда проверки зелёные.
3. Не отключать хук и не обходить его: блокировка — это и есть feedback loop.
   Если проверка кажется ложной, сначала разобраться, потом менять harness
   отдельным осознанным решением.

## Рискованные изменения

- Новая ветка:
  ```bash
  git switch -c experiment/<тема>
  ```
- Изолированная копия, не трогающая рабочее дерево:
  ```bash
  git worktree add ../claude_dev-experiment -b experiment/<тема>
  ```
- Откат в рамках сессии — `/rewind`; откат к коммиту — `git restore` / `git reset`
  (жёсткий сброс запрещён permission-правилами).

## Критерий готовности задачи

- `npm run lint`, `npm run typecheck`, `npm run build` проходят.
- Приложение запускается, изменение показано и объяснено.
- Изменение зафиксировано коммитом (чекпоинт существует).

## Осознанные послабления

- Маркер `[без вопросов]` в запросе отключает гейт на 3 вопроса. Использовать
  только когда задача действительно полностью определена.
- Агент может работать в plan mode без правок — это не нарушает цикл, а
  переносит решение на шаг 3.
