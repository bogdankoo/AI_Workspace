# ADR 0001. Harness агента в репозитории

- **Статус:** принято
- **Дата:** 2026-10-25
- **Этап роадмапа:** Stage 2, пункт 14 «Harness Engineering»

## Контекст

Агент (Claude Code) уже работал с проектом, но его границы существовали только
в двух местах: текстом в `CLAUDE.md` и глобальными хуками в `~/.claude`. Из этого
следуют три проблемы:

1. Правила «не трогай `.env`», «проверяй результат» не enforced — это просьбы,
   а не технические ограничения.
2. Хуки не входили в репозиторий: на другой машине или в новой сессии поведение
   агента не воспроизводилось.
3. Не был описан рабочий цикл и точки отката, поэтому цена ошибки зависела
   от дисциплины, а не от процесса.

Нужен воспроизводимый workflow разработки **в репозитории**, а не в личных
настройках.

## Решение

Harness разделён на шесть слоёв. Каждый слой отвечает на свой вопрос и живёт
в конкретном файле проекта.

| Компонент | Вопрос | Где в проекте |
|---|---|---|
| Agent harness | Кто вообще исполняет цикл «модель → инструмент → результат» | Claude Code + `.claude/settings.json` (регистрация хуков) |
| Execution environment | Где исполняются инструменты и что они могут задеть | Рабочая директория проекта, git-ветки/worktree, sandbox-режим Claude Code |
| Instructions | Что делать и как | `CLAUDE.md`, `AGENTS.md`, `docs/`, `.claude/hooks/*.mjs` |
| Permissions | Что разрешено технически | `.claude/settings.json` → `permissions.allow/ask/deny` |
| Checkpoints | Как откатить | git-коммиты, ветки, `/rewind`, plan mode |
| Feedback loops | Как узнать, что результат верный | `.claude/hooks/turn-checks.mjs` (`lint` + `typecheck`), `npm run build`, `ui-verify` |

### Permissions

- `deny` — инструменты `Read`/`Edit`/`Write` не могут читать и менять `.env*`,
  плюс запрет на `rm -rf`, `git reset --hard`, `git push --force`,
  `git clean -fd*`. Эти действия необратимы или раскрывают секреты, поэтому
  запрещены на уровне движка, а не текстом.
- `ask` — `git push`, `git clean`, `npm install`, `npx`, обычные `rm`/`mv`.
  Необратимые или меняющие окружение действия требуют подтверждения.
- `allow` — только проверки и чтение состояния: `npm run lint|typecheck|build|dev`,
  read-only git, `ls`.

Важное ограничение: правила `Read`/`Edit` — это guardrail для инструментов
Claude Code, а не sandbox. Прочитать `.env` через произвольную shell-команду
теоретически всё ещё можно. Полная изоляция достигается execution environment
(sandbox, отдельный пользователь, отсутствие файла), а не списком запретов.

### Hooks

Скрипты перенесены из `~/.claude/hooks/` в `.claude/hooks/` и зарегистрированы
в проектном `.claude/settings.json` через `${CLAUDE_PROJECT_DIR}`.

- `clarify-before-edit.mjs` — `UserPromptSubmit` + `PreToolUse` (Edit/Write):
  до первой правки требует минимум 3 содержательных уточняющих вопроса.
- `turn-checks.mjs` — `PostToolUse` запоминает изменённые файлы, `Stop`
  запускает `lint` и `typecheck`. Если проверки упали, остановка блокируется
  и агент получает список ошибок для исправления.

`build` сознательно не входит в `Stop`: он заметно медленнее и запускается
вручную как часть критерия готовности.

### Checkpoints

- Перед рискованным изменением — коммит или отдельная ветка.
- Plan mode — чекпоинт до правок: сначала план, потом исполнение.
- `/rewind` — откат состояния сессии.
- `git worktree` — изолированная копия для эксперимента, не трогающая рабочее дерево.

## Последствия

**Плюсы**

- Поведение агента воспроизводится из репозитория: достаточно склонировать проект
  и запустить Claude Code.
- Правила стали проверками: нарушение не зависит от того, «вспомнил» ли агент
  инструкцию.
- Ошибки ловятся автоматически до того, как ход считается завершённым.
- Критерий пункта 14 проверяем: каждый компонент указывает на конкретный файл.

**Минусы и ограничения**

- Хуки требуют Node.js в окружении.
- Глобальный гейт на 3 вопроса больше не действует в других проектах — это
  осознанный выбор в пользу проектной воспроизводимости.
- `Stop` проверяет `lint` и `typecheck`, но не тесты и не `build`; полная
  проверка остаётся ручным шагом перед сдачей.

## Как проверить

1. Попросить агента прочитать `.env` — должен сработать `deny`.
2. Внести заведомую ошибку типов — `Stop` должен заблокировать завершение хода.
3. Запросить правку файла, не задав 3 вопросов — `PreToolUse` должен запретить
   `Edit/Write`.
4. Убедиться, что `git status` и содержимое `.claude/settings.json` объясняют
   каждый слой таблицы выше.
